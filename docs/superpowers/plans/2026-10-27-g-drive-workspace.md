# G드라이브 작업 환경 통합 계획

> **For agentic workers:** Use subagent-driven-development for the path migration and independent review.

**Goal:** 편집 소스와 모든 Vercel 관람 자산, 실행 도구를 영락역사관 폴더에 두고 E드라이브 없이 수정·검증·배포 명령을 사용할 수 있게 한다.

**Architecture:** 기존 편집 원본 `museum-web`과 실행 사본의 분리를 유지한다. 실행 경로만 형제 폴더 `../museum-workspace`로 상대 지정하여 드라이브 문자에 의존하지 않게 한다. E드라이브가 없으므로 매니페스트의 공개 아카이브에서 사진·파노라마를 해시 검증하여 복원한다. 자산 ZIP 중복 보관은 생략한다.

**Tech Stack:** PowerShell mutex wrapper, Node.js, npm, Vite, Vercel CLI.

**Scope:** 사용자가 요청한 기존 환경의 경로 이전이며 웹사이트 기능 변경과 실제 공개 배포는 포함하지 않는다. 업체 백업과 이전 작업 폴더를 보존한다.

## 제약과 검토 사항

- 현재 G Google Drive의 로컬 여유 공간은 약 5.6GB. 사용자는 C 정리를 하지 않고 현재 공간에 자산을 담도록 지시했다. 로컬 빌드는 공개 자산 복사를 생략하고 미리보기는 컴파일 결과와 기존 public을 함께 제공한다. 원격 Vercel 빌드는 기존 완전한 자산 복원 방식을 유지한다.
- 원래의 카탈로그·개별 파일·ZIP 해시 검증, 경로 검사, 실행 잠금, 팀·프로젝트 확인 유지.
- 로그인 비밀은 사용자 프로필에 유지하고 G 공유 폴더에 복사하지 않는다.
- 수정/추가/삭제 동기화와 Google Drive 파일 동작을 실제 확인한다.
- G드라이브의 클라우드 업로드 완료 여부와 오프라인 고정은 파일 존재와 구분한다.
