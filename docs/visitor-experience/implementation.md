# 영락교회 디지털역사관 관람 편의 개선 구현·검증 보고서

2026-10-04 기준. 설계와 구현 계획을 적용한 결과를 정리한다. [설계안](design.md)과 [원래 구현 계획](plan.md)은 제안 당시의 기록으로 보존한다. 기존 복원본을 유지하고, 사용자 지시에 따라 개선본을 별도 Vercel 프로젝트로 배포한다.

## 구현한 여섯 단계

| 단계 | 구현 결과 |

| 1. 입장·모바일 도구 | 관람 시작 한 번으로 로비에 진입한다. 직접 전시 링크에는 입장 안내를 강제하지 않는다. 하단 전시실·자료 보기·검색·더보기, 44px 주요 버튼, 화면 안전영역, 한국어 도움말을 제공한다. 배경 음악은 재생을 요청한 뒤에만 준비한다. |

| 4. 자료 검색·연결 | 실제 HTML 225개에서 제목·문단·이미지를 추출하고 본문은 필요할 때 읽는다. 인물·연도·주제 검색, 전시실/자료 종류 필터, 위치·발췌, 글로 읽기·공간에서 보기를 제공한다. 같은 자료의 다른 전시 맥락과 원래 연결되지 않은 자료도 목록에서 접근할 수 있다. 역사 설명을 새로 만들어 넣지 않았다. |
| 5. 성능·고장 복구 | 공간/사진 확대 엔진을 지연 로딩한다. 자동·높음·절약 화질, 1024px 중간 파노라마, 360px 썸네일·1280px 사진 미리보기, 명시적 원본 확대를 제공한다. 빠른 이동에서는 마지막 선택이 적용되고, 이전 페이지의 늦은 마커가 새 전시에 붙지 않는다. 이미지·모듈 오류에는 설명과 재시도/현재 화면 새로고침을 제공한다. |
| 6. 이어보기·공유·추천 관람 | 기기 저장을 이용한 최근 위치·책갈피·글자/화질 설정, 제목과 주소 공유, 처음부터 보기, 핵심/역사/사진 코스를 연결했다. 사진 코스는 실제 존재하는 서로 다른 다섯 갤러리를 사용한다. 저장이 차단되거나 데이터가 손상되어도 관람 진입이 막히지 않는다. |

## 원본 보존과 링크 호환

원본 64개 공간, 207개 전시 페이지와 실제 제공된 HTML 225개를 유지했다. 원본 메타데이터에 등록된 HTML은 224개이며, 전달 폴더에 추가로 존재한 `html/a02_01.html`을 포함해 225개를 접근 가능한 자료로 정리했다. 본문·사진을 보존하면서 표시용 제목과 탐색 연결을 별도 데이터로 관리한다.

원본 자산 8,028개의 해시 비교에서 변경이 없었다는 루트 검증 결과를 확인했다. `full-museum.json`, 원본 미디어 폴더와 배포 자산 명세는 변경하지 않았다. C–E 왕복 연결과 원본 큐브 상·하단 방향 보정도 유지한다. 알려진 결손 파일의 안내와 원본 대체 사진·관련 사진 표시를 보존했다.

기존 `startscene`, `page`, `startlookat`, `exhibit` 공유 링크를 계속 해석한다. 새 `mode=read`는 선택적이며, 기존 주소는 공간 관람으로 열린다. 자료 안의 사진 확대와 브라우저 뒤로가기에서도 전시 맥락을 유지한다. 시험 사이트의 `noindex`는 그대로 유지한다.

## 성능 자산과 측정 범위

| 항목 | 결과 |
| --- | --- |
| 신규 버전 자산 | WebP 1,566개, **100,076,464바이트**(약 95.44MiB) |
| 중간 파노라마 | 원본 2048px 파노라마 62곳의 큐브 면 372개를 1024px로 생성. 기존 확장 E실 두 곳의 1024px 원본은 유지 |
| 사진 미리보기 | 갤러리 사진 597개의 360px 썸네일과 1280px 미리보기 |
| 큰 사진 10개 | 원본 합계 31,599,576바이트 → 미리보기 2,367,468바이트, **92.51% 감소** |
| 파노라마 자산 비교 | 원본 2048px 상세 타일 142,335,685바이트 → 1024px 면 23,220,002바이트 |
| 캐시 | 해시가 포함된 신규 `/visitor-assets/8226aa914387cb84/`만 장기 불변 캐시. 원래 `/media/full/` 재검증 정책은 유지 |
| 공개 배포 첫 화면 JS | 기존 393,304바이트 → 개선본 135,371바이트, **65.58% 감소**. 각 5회 모두 같은 값 |

큰 사진은 미리보기부터 받고 원본 확대를 눌러야 원본을 추가로 받는다. 자동 화질은 화면 폭·지원되는 기기/통신 정보를 참고하며 사용자가 고른 화질을 우선한다. 절약 모드에서는 기본 파노라마만 사용한다. 다음 공간 하나의 기본 면만 지연 준비하며, 절약/데이터 절약 상태에서는 이를 하지 않는다.

위 수치는 생성된 자산 크기와 요청 구조의 비교다. 동일한 실제 휴대폰·통신망에서 측정한 로딩 시간, LCP/INP/CLS 개선치로 해석하면 안 된다. 전체 역사관 선로딩이나 기존 대용량 배포 아카이브 재포장은 하지 않았다. 상세 수치는 [미디어 측정 JSON](media-metrics.json), 구현 방식은 [성능 구현 보고서](../performance-report.md)에 있다.

첫 화면 JS는 공개된 두 주소를 Chrome 1440×900, 캐시 비활성, 다운로드 10Mbps·업로드 5Mbps·지연 80ms에서 각각 5회 측정한 압축 전송 본문 크기다. 개선본은 입장 선택 화면에서 3D 엔진을 받지 않는다. 개선본 안내 준비 시간은 670/542/563/564/541ms(중앙값 563ms), 기존 외관 파노라마 준비 시간은 2347/2437/2506/2558/2472ms(중앙값 2472ms)였다. 두 준비 시점의 기능이 다르므로 시간 단축률로 비교하지 않는다. 실제 휴대폰의 시간이나 Core Web Vitals를 측정한 결과가 아니다. 원시 결과는 [브라우저 측정 JSON](browser-metrics.json)에 보관했다.

원본 배포 복원은 기존 공개 아카이브 808,894,571바이트를 재사용한다. 새 미리보기 약 95.44MiB만 추가했으며 새로운 Blob 업로드·유료 서비스·요금제 변경은 없었다. 읽기/공간/사진 확대에 필요한 모듈과 자산만 방문 시점에 요청한다.

## 검증 결과

최종 자동 검사 **66/66**, TypeScript 검사, 로컬 Vite 빌드가 통과했다. Vercel에서도 원본 자산 8,028개를 복원·검증한 뒤 TypeScript와 Vite 빌드가 통과했다. 기존 URL·전시 연결·검색·저장 오류·본문/이미지 처리·원본 평면 투영 등을 검사한다. 공간 엔진과 전체 전시 데이터의 일부 지연 청크가 500kB를 넘어 Vite 경고가 남지만 첫 화면에 모두 로딩되지는 않는다.

Chrome 브라우저에서 360×800, 390×844, 768×1024, 1440×900, 844×390 가로 화면의 다섯 뷰포트를 확인했다. 입장→로비→A실 설명→사진 확대→본문/전시 복귀→C실→확장 E실의 주요 동선, 읽기 모드·검색·설정·공유·직접 링크를 확인했다. 이것은 브라우저 화면 크기 검사이며 실제 휴대폰 검사와 구분한다.

실제 새 공개 주소에서도 입장 중복 클릭, 원래 C실 raw-plus 링크, 확장 E실 바로가기, 화질 변경 직후 읽기 전환, 검색, 본문 사진 복귀, 책갈피·글자 설정 저장, 위 다섯 화면 크기를 다시 확인했다. 화질 변경→읽기 전환 검사는 남은 WebGL 캔버스 0개·발생한 pageerror 0개로 통과했다. 주요 버튼은 44px 이상이고 가로 넘침은 없었다. 촘촘한 원본 지도는 승인된 작은 목표 예외를 유지하며 큰 방 목록으로 같은 위치에 접근할 수 있다.

별도 Chrome 고장 주입 검사에서는 WebGL 미지원 상태의 읽기 진입, localStorage 접근 차단, 느린 파노라마 중 연속 이동과 즉시 읽기 전환, 미리보기 실패의 원본 대체, 원본 이미지 실패 후 복구를 확인했다. 마지막으로 실패했던 여섯 경우를 새 페이지에서 다시 검사해 모두 복구를 확인했다.

| 최종 고장 복구 재검사 | 결과 |
| --- | --- |
| 자료 화면 모듈 실패 후 새로고침 | 전시/자료 URL을 보존하며 사진 대화상자 복구 |
| 공간 뷰어 모듈 실패 후 새로고침 | `startlookat=10,0,100`을 포함한 주소 보존, 공간 캔버스 복구 |
| 본문 데이터 모듈 실패 후 새로고침 | 같은 전시의 읽기 화면 복구 |
| 사진 확대 엔진 실패 후 새로고침 | 같은 갤러리 `exhibit` 유지, 원본 확대 복구 |
| 본문 로딩 3초 지연 중 검색 Enter | 문서 재탐색 없음, ‘한경직’ 입력 유지, 124개 결과 표시 |
| 미리보기와 원본 모두 404 후 재시도 | 읽을 수 있는 오류·재시도·새로고침 표시, 통신 복구 후 1280px 미리보기 표시 |

실제 iOS Safari·Android Chrome, 보조 기술 사용자의 연속 관람, 초보자 5~8명 사용성 검사는 **아직 실시하지 않았다**. ‘설명 없이 60초 안에 첫 전시 열기 80%’는 설계 목표이며 달성 수치로 보고하지 않는다.

## 배포와 되돌리기

기존 [원본 복원본](https://youngnak-museum-poc.vercel.app)은 유지했다. 개선본은 사용자 지시에 따라 별도 `youngnak-museum-ux` 프로젝트에 **배포 완료(READY)** 했다. [개선본 열기](https://youngnak-museum-ux.vercel.app)에서 HTTP 200과 실제 관람을 검증했다. 두 사이트의 noindex가 유지되며, 기존 사이트 JS는 `index-Dl8-wAIa.js`, 개선본은 `index-BXy46_sS.js`로 별개다.

- 배포 ID: `dpl_HyiNice5zDi28oZKPzNcuyMN4EDb`
- 배포 고정 URL: https://youngnak-museum-c5hxjp24b-postsun17-webs-projects.vercel.app
- 구현 소스: `feat/visitor-experience` 브랜치, 배포 당시 `3ac5096`
- 원본 비교·복구 기준: `main`의 `fa8743186180ba5af74662d24b6ef12eb656a4d5`
- 공개 정적 사이트로 서버 함수는 추가하지 않았다. 브라우저 오류를 검사했으며 별도 운영 모니터링/실사용자 측정은 구성하지 않았다.

별도 프로젝트로 배포하므로 개선본의 이전 배포로 되돌리거나 안내 링크를 원본 복원본으로 돌릴 수 있다. 원본 프로젝트를 덮어쓰는 방식으로 되돌릴 필요가 없다. 신규 자산은 기존 원본과 다른 버전 경로를 사용한다.

## 초보 관람객 5~8명 확인용 짧은 체크리스트

관리자가 기능을 미리 설명하지 않고, 참가자별 성공 여부·시간·막힌 지점·기기/브라우저를 기록한다.

- [ ] 링크를 열고 60초 안에 첫 전시를 연다. 필요한 설명이나 도움을 기록한다.
- [ ] 현재 전시실과 주제를 말하고, 로비 또는 다른 방으로 이동한다.
- [ ] 자료를 찾아 글자를 크게 바꾸고, 사진을 확대한 뒤 읽던 자리로 돌아온다.
- [ ] ‘한경직’ 또는 관심 있는 주제를 검색하고 관련 설명을 읽는다.
- [ ] 전시 주소를 공유하고, 같은 자료·위치로 다시 열리는지 확인한다.
- [ ] 책갈피/이어보기를 사용하고, 뒤로가기·가로 화면에서도 관람을 이어간다.
- [ ] 가장 헷갈린 버튼과 빠진 설명을 한 가지씩 말한다.

실기기 단계에서는 iOS Safari와 Android Chrome의 화면 회전, 큰 글자, 키보드·음성 보조, 재방문, 뒤로가기, 10분 연속 관람을 별도로 점검한다.
