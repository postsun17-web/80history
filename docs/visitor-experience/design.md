# 영락교회 디지털역사관 관람 편의·성능 개선 설계안

작성일: 2026-10-04
검토 대상: https://youngnak-museum-poc.vercel.app/
소스 기준: 80history/main, fa8743186180ba5af74662d24b6ef12eb656a4d5
상태: 개선 아이디어 제안. 제품 코드·배포·요금제는 변경하지 않았다.

## 목표와 대상

PC와 모바일에서 처음 방문한 사람이 회원가입이나 조작 설명을 길게 읽지 않고도 전시를 찾고, 내용을 읽고, 원래 위치로 돌아오도록 한다. 스마트폰 조작이 익숙하지 않은 관람객과 작은 글씨를 읽기 어려운 관람객도 포함한다고 가정한다.

핵심 방향은 **360도 공간 관람 + 글·사진 중심의 편한 읽기**를 같은 전시 데이터와 위치 정보로 연결하는 것이다. 기존 파노라마·전시·C–E 이동·원본 링크를 유지한다. 새로운 유료 뷰어, 회원 시스템, AI 챗봇은 이 개선에 필요하지 않다.

## 확인한 현황과 검토의 한계

- 지도, 현재 위치·방향, 전체 공간 목록, 공간별 자료, 전시 이전/다음, 크게 보기, 자료별 URL, 브라우저 뒤로가기는 이미 구현돼 있다. 이를 새로 만든다고 계획하지 않는다.
- 데스크톱 입장 안내를 닫은 뒤에도 외부 입구에 머무는 동작을 실제 확인했다. 현재 '입장하기'는 안내만 닫으며 로비 이동은 별도 동작이다.
- 데스크톱 전시와 390×844 모바일 크기의 전시/크게 보기 화면을 확인했다. 모바일 측정은 브라우저 화면 크기 검사이며 실제 iPhone·Android 기기 검증은 아니다.
- 해당 모바일 화면의 버튼 사각형은 전체 공간 목록 약 18×14px, 전시 이전/다음 25×29px, 크게 보기 65×29px, 확대·축소 33×33px, 배경 음악 25×25px였다. 도움말 버튼은 모바일에서 숨겨진다.
- 긴 연혁 판넬을 크게 보아도 가로 이미지 전체 맞춤 상태여서 다시 확대하고 좌우로 움직여야 읽을 수 있었다. 이미지 확대 기능 자체는 정상 작동한다.
- 64개 공간은 전체 공간 목록에서 한 목록으로 나열된다. 일부 자료명은 '사진 1', '자료 3' 같은 일반 이름이다.
- 이미 본문 HTML 224개가 있다. 모든 설명을 OCR로 새로 만드는 접근은 불필요하다. 전시 페이지와 본문은 반드시 일대일 대응한다고 가정하지 않는다.
- 배포 manifest의 활성 자산은 8,028개, 807,639,053바이트(약 770MiB)다. 이것은 전체 파일 합계이며 최초 접속 때 모두 받는 양이 아니다.
- 파노라마는 이미 저해상도 기본 이미지와 보이는 방향의 타일을 사용한다. 팝업 종료 시 뷰어·영상 정리, 일부 표지 지연 로딩, 로딩 재시도도 구현돼 있다.
- 소스상 전체 전시 JSON과 콘텐츠 확대 프로그램이 초기 모듈에 포함된다. 일부 사진은 확대 프로그램이 단일 이미지 전체를 읽는다.
- 실제 휴대폰 FPS·메모리, LCP/INP, 첫 방문 전송량, 대표 동선 소요 시간은 아직 실측하지 않았다. 아래 수치는 개선 후 목표다.

## 접근 방법 비교

| 방법 | 장점 | 범위·한계 |
| --- | --- | --- |
| 기존 화면의 버튼·글씨만 정리 | 빠르게 적용 가능 | 360도 조작과 긴 이미지 읽기의 어려움은 남음 |
| **360도와 편한 읽기를 연결 — 추천** | 몰입감, 정보 접근성, 저성능 기기 대응을 함께 개선 | 자료 제목·전시 연결 정리와 읽기 화면 필요 |
| 전면 재설계·플랫폼 교체 | 큰 구조 변경 가능 | 현재 복원 성과와 검증을 다시 다룰 비용이 큼 |

첫 단계에 버튼 정리를 적용하되, 최종 방향은 두 번째 방식으로 잡는다.

## 제안하는 관람 흐름

첫 화면에서 큰 '관람 시작' 버튼을 누르면 실제 로비로 이동한다. 외관 감상은 별도 선택으로 유지한다. 옆에는 '글과 사진으로 보기'를 제공한다. 도움말은 '화면을 움직여 둘러보기 / 이동 버튼 누르기 / 자료 읽기'의 짧은 안내로 바꾸며 언제든 다시 볼 수 있다.

공간 안에서는 현재 위치와 전시 제목을 확인하고 '자료 보기'를 누른다. 설명·사진·음성·영상 중 제공되는 자료를 고른다. 읽기를 마치면 정확히 원래 공간·시선·페이지로 돌아온다. 사진을 크게 열었을 때는 '본문으로'와 '전시로'를 구분한다.

검색과 추천 코스에서도 같은 자료 URL을 사용한다. 관람 방식이 바뀌어도 서로 다른 콘텐츠를 중복 관리하지 않는다.

### 화면 규칙

- 모바일은 주요 도구 4개를 하단에 모으고 음악·전체 화면·도움말·외부 링크는 더보기에 둔다. 검색이 완성되기 전에는 동작하지 않는 탭을 노출하지 않는다.
- PC에서는 전시 메뉴와 현재 위치를 유지하며 자료를 읽을 때 넓은 측면 패널 또는 읽기 화면을 제공한다.
- 주요 터치 영역은 최소 44×44 CSS px로 설계한다. 밀집 지도점은 무조건 넓혀 겹치게 만들지 않고 큰 전시실 선택·목록을 동등한 대안으로 제공한다.
- 본문 글자 18/21/24px, 행간 1.7, 긴 문장 폭 최대 68ch. 기기 글자 확대와 세로/가로 화면에서도 접근 가능한 닫기 버튼을 유지한다.
- 공간 안 이동과 다음 전시 페이지를 다른 이름으로 표시한다. 전시 페이지 끝에서는 '다음 전시'를 안내한다.
- 지도·메뉴·검색에서 선택한 전시는 정면의 읽기 좋은 시점으로 도착하고, 실제 공간을 따라 이동하는 화살표는 원본 동선의 방향감을 유지한다.
- 기존 모달의 Escape 닫기·포커스 복귀를 보존한다. 새 메뉴·읽기 화면에도 적용한다.
- 자동 회전·음악은 강제하지 않는다. 동작 줄이기 설정에서는 입장 연출을 생략한다.
- E실은 '확장 전시실'로 일관되게 표시한다. 전시 내용이 준비되기 전에는 핵심 역사 코스에 억지로 포함하지 않는다.
- 답변 서버가 없는 챗봇은 검색·관람 도움말보다 앞에 내세우지 않는다.

### 자료 정리 원칙

기존 제목·본문·사진을 우선 사용한다. 첫 문단을 잘라 만든 긴 제목, 일반적인 자료명, 전시 연결이 없는 자료부터 정리한다. 본문이 이미지에만 있는 경우에 한해 필요한 범위를 추출하고 사람이 대조한다. 역사적 연도·인물·사진 설명·추천 코스의 내용은 원자료로 검수하며 임의로 생성하지 않는다.

## 성능 개선 방향

1. 입장 화면과 전시 목록을 먼저 표시한다. 360도 엔진, 사진 확대 프로그램, 전시별 상세 데이터는 필요한 시점에 로딩한다. 글·사진 모드는 WebGL 초기화 없이도 열린다.
2. 기존 타일 로딩에 모바일용 중간 화질을 더한다. '자동 / 선명하게 / 데이터 절약'을 제공한다. 지원되는 기기·네트워크 정보는 참고 신호로만 쓰며 사용자 선택을 우선한다.
3. 큰 사진은 화면 크기에 맞는 미리보기부터 표시한다. 확대 요구가 큰 사진부터 다단계 타일을 시범 적용한다.
4. 다음 방의 기본 이미지 한 곳만 여유 시간에 준비한다. 데이터 절약 모드에서는 선로딩하지 않는다. 전체 역사관을 먼저 받지 않는다.
5. 이미지 주소에 버전·해시를 넣은 뒤 장기 캐시를 적용한다. 기존 동일 주소에 캐시 기간만 늘려 수정 자료가 남는 문제를 만들지 않는다.
6. 음악은 재생을 눌렀을 때 로딩한다. 중요하지 않은 마커 하나가 늦어져도 주요 이동과 설명 열람을 기다리게 하지 않는다.
7. 빠르게 여러 방을 눌렀을 때 마지막 선택이 최종 화면이 된다. 이전 화면의 요청이 늦게 끝나 새 화면을 덮지 않는다.
8. 파노라마 실패 시 재시도·이전 공간·자료로 보기, 외부 영상 실패 시 원본 링크·가능한 설명을 제공한다.
9. 썸네일·화질 단계 추가 후 Blob 저장량, 배포 복원량, CDN 요청 수·전송량을 함께 점검한다. 새로운 유료 서비스 가입은 기본 범위에 넣지 않는다.

## 완료 기준과 점검

- 초보 관람객 5~8명의 소규모 확인에서 80% 이상이 별도 설명 없이 60초 안에 첫 전시를 연다. 이는 사용성 목표이며 현재 측정 결과가 아니다.
- 현재 공간에서 핵심 설명 또는 다른 전시실까지 선택 2회 이내를 목표로 한다.
- 360×800, 390×844, 768×1024, 1440×900 및 휴대폰 가로 화면에서 핵심 버튼이 겹치거나 잘리지 않는다.
- 확대된 사진을 닫으면 읽던 문단으로, 자료를 닫으면 원래 공간·페이지·시선으로 돌아온다.
- 실제 iOS Safari와 Android Chrome에서 키보드/음성 보조·회전·재방문·뒤로가기·10분 연속 관람을 확인한다.
- LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하를 장기 목표로 삼되 파노라마의 '관람 가능 시간'은 별도로 측정한다.
- 성능 비교는 같은 기기·네트워크·대표 경로에서 수행한다. 초기 JS 전송량 30% 감소, 큰 사진 10개의 최초 표시 전송량 50% 감소를 우선 목표로 두며 품질·데이터 절약 효과를 실측한다.
- 기존 64개 공간·207개 전시 페이지·공유 URL·C–E 연결·교회 상단 방향 수정의 회귀를 검사한다.
